# DNRE · Кок-Жайлау — панель расчётов и сверки геометрии

Сценарная панель (Streamlit) к монографии «Динамическое природно-рекреационное равновесие (DNRE): Кок-Жайлау».
Расчёты — порт пакета DNRE v1.0 (Zenodo, DOI 10.5281/zenodo.23107585). Панель не является независимой валидацией метода.

**Статус пространственной сверки: SPATIAL / INDETERMINATE.** Геометрия четырёх кадастровых участков получена из неофициального
источника и требует официального подтверждения; официальный статус границ в ЕГКН — ND.

**Онлайн-панель (запущена 08.11.2026):** https://dnre-kok-zhailau-lqjl8yc46daokktwkoivxn.streamlit.app

## Запуск
```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py                                   # панель, http://localhost:8501
python tests/test_core.py                              # проверки расчётов (или: python -m pytest -q)
python scripts/run_reconciliation.py                   # пересчёт сверки -> results/
```
Проверено на Python 3.13 с версиями из `requirements.txt`.

## Вкладки
1. Зимний водный приоритет (P = 25/50/75/95 %): свободный сток XI–III, бытовой спрос обслуживается раньше снега (допущение автора, не юридический приоритет).
2. Помесячный баланс XI–X со сценарием возврата воды снегопушек.
3. Рекреационная нагрузка: N = суточные × время катания / часы работы; ёмкость CCC при пределах плотности 10–40 чел/га (чувствительность, не нормы).
4. Нормированный запас и решение PASS / FAIL / INDETERMINATE.
5. Карта контуров по 96 точкам и контроль геометрии.
6. Кадастр ↔ точки: сверка загруженных или встроенных (неофициальных) полигонов.

## Данные (подробно: `data/provenance/SOURCE.md`)
- `project_coordinates.csv` — 96 опубликованных точек (ОоВВ 2026, через пакет DNRE v1.0).
- `cadastre_declared.csv` — 4 заявленных кадастровых номера, сумма 1002,0000 га.
- `parcels_unofficial_osmanov.geojson` — **неофициальная** геометрия 4 участков (OSMANOV.KZ, 2026-11-08).

## Методы
- Нормированный запас: upper `m = (B − L)/(B − R)`, lower `m = (L − B)/(R − B)`; решение по интервалу [low, high]: PASS при low > 0, FAIL при high < 0, иначе INDETERMINATE. ND не заменяется нулём.
- Площади двумя способами, всегда отдельно: **геодезически** — `pyproj.Geod`, эллипсоид WGS84, вход EPSG:4326; **плоско** — Shapely в UTM 43N (EPSG:32643).
- Валидность — Shapely/GEOS. Геометрия **не исправляется** (`make_valid` не применяется), не упрощается и не подгоняется под 1002 га.
- Точки считаются «внутри», если лежат внутри или на границе объединения кадастровых геометрий (UTM 43N).

## Ограничения и оставшиеся ND
- Назначение и порядок соединения точек 1–88 и 89–96 не установлены; контур 1–88 не является установленной границей проекта; связь точек 89–96 с каким-либо объектом не доказана.
- Исходная СК, дата актуальности и происхождение геометрии OSMANOV.KZ, а также официальный статус границ в ЕГКН — ND.
- Из сравнения не делается выводов о законности или достоверности границ.
- Сырые JSON-ответы источника и SHA256SUMS должны быть добавлены в `data/provenance/raw/` (в этот репозиторий не передавались).
- Данные расчётов водного баланса и рекреации — сценарные допущения пакета DNRE, не измерения.
